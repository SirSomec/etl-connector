# Дашборд «Анализ регионов»

Код: `src/regionAnalysisDashboard.js`. Маршрут: `/dashboards/region-analysis`.

Экран анализирует один выбранный регион по `mg_workplaces.address__region`. Он помогает оценить спрос и выполнение в регионе и перейти к проблемным городам в дашборде «Анализ городов».

## Фильтры

- обязательный регион;
- период `from`/`to`, по умолчанию последние 90 дней;
- периодизация день, неделя или месяц;
- в серверной модели предусмотрены фильтры по бренду, специальности и типу заказа.

## Блоки

- KPI: заказано, свободный заказ, SLA, покрытие, отработано и отмены;
- динамика заказа, свободного заказа, SLA, покрытия и выполнения;
- города: заказ, свободный заказ, SLA, покрытие, выполнение и число точек;
- специальности с теми же показателями;
- очередь внимания: города с незакрытым спросом, упорядоченные по его объему.

## Доменные правила

- используются таблицы `mg_orders`, `mg_jobs`, `mg_clients`, `mg_workplaces`, `mg_contractors`, `mg_professions`;
- в расчеты попадают только актуальные заказы: не удаленные, не скрытые, без тестовых клиентов и контрактов `processing`;
- смены связываются с заказом через `mg_jobs.source = mg_orders._id`;
- закрывающими спрос считаются `booked`, `going`, `inprogress`, `checkingin`, `checkingout`, `completed`, `delayed`, `waiting` и успешные `confirmed`;
- успешные `confirmed` используют общий helper исключения прогулов.

Новые метрики имеют SQL-info metadata и отображаются только при наличии права `SQL метрик`.
