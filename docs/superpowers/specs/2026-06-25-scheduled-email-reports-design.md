# Scheduled Email Reports Design

## Цель

Добавить в ETL Analytics Service систему регулярной отправки Excel-отчетов по email. Администраторы и аналитики с отдельными правами должны создавать SQL-отчеты через UI, настраивать расписания и получателей, смотреть историю отправок и скачивать отправленные `.xlsx` файлы за последние 60 дней.

## Контекст

Проект уже использует:

- Express и server-rendered HTML без frontend build step;
- управляемые пользователи и права доступа в `src/auth.js`;
- админские экраны `/admin/users`, `/admin/preload`, `/admin/activity`;
- SQLite runtime-хранилища в `data/` для предзагрузки и активности;
- планировщик `preloadScheduler` с пересчетом ближайшего запуска через `setTimeout`;
- ClickHouse read-only клиент для аналитических запросов;
- запрет произвольного SQL в обычном UI дашбордов.

Новая система является отдельным административно-аналитическим инструментом. Она не меняет существующие дашборды и не добавляет произвольный SQL в публичные аналитические экраны.

## Права Доступа

Добавляются три независимых права:

- `scheduled-report-author`: создание, редактирование и проверка SQL-отчетов; настройка названия, описания, SQL, лимита строк и таймаута.
- `scheduled-report-delivery`: управление расписаниями, временем отправки, получателями, темой и текстом письма; просмотр истории отправок; скачивание отправленных `.xlsx`; ручной запуск отправки.
- `mail-settings-admin`: настройка SMTP и тест отправки. Это право доступно только администраторам; аналитикам оно не выдается через UI.

Администратор получает все права автоматически, как и остальные admin-only возможности. Аналитик может получить `scheduled-report-author`, `scheduled-report-delivery` или оба права независимо.

Backend проверяет права на каждом маршруте. UI скрывает недоступные формы и действия, но не полагается на это как на механизм безопасности.

## SQL Безопасность

SQL-конструктор разрешает только read-only запросы:

- запрос должен начинаться с `SELECT` или `WITH` и после CTE приводить к `SELECT`;
- запрещены несколько statements в одном запросе;
- запрещены `INSERT`, `UPDATE`, `DELETE`, `ALTER`, `DROP`, `TRUNCATE`, `CREATE`, `RENAME`, `OPTIMIZE`, `SYSTEM`, `KILL`, `ATTACH`, `DETACH`, `GRANT`, `REVOKE`;
- запрос выполняется через read-only ClickHouse пользователя из текущей конфигурации;
- запрос выполняется как подзапрос с внешним `LIMIT`, если пользовательский SQL не задает меньший лимит;
- для каждого запуска применяются таймаут и максимальный размер результата;
- ошибки очищаются от секретов перед сохранением и показом.

В первой реализации SQL хранится как часть определения отчета в `data/scheduled-reports.sqlite`. Activity-log не пишет тело SQL, чтобы не разносить потенциально чувствительные запросы по дополнительным журналам.

## Модель Данных

Все состояние системы рассылок хранится в новом SQLite-файле:

```text
data/scheduled-reports.sqlite
```

Файлы отправленных отчетов хранятся отдельно:

```text
data/scheduled-report-files/<run-id>.xlsx
```

Основные таблицы:

- `scheduled_reports`: `id`, `title`, `description`, `sql`, `enabled`, `row_limit`, `timeout_ms`, `created_by`, `updated_by`, `created_at`, `updated_at`.
- `scheduled_report_schedules`: `id`, `report_id`, `enabled`, `schedule_time`, `timezone`, `recipients_json`, `email_subject`, `email_body`, `created_by`, `updated_by`, `created_at`, `updated_at`.
- `scheduled_report_runs`: `id`, `report_id`, `schedule_id`, `trigger`, `status`, `started_at`, `finished_at`, `row_count`, `file_size_bytes`, `file_path`, `recipients_json`, `error_message`, `created_by`.
- `mail_settings`: SMTP `host`, `port`, secure mode, username, password secret value in runtime SQLite, `from_email`, `from_name`, timestamps and masked status fields.

Один отчет может иметь несколько расписаний. Одно расписание может отправлять отчет на один или несколько email-адресов.

Файлы и записи истории для скачивания хранятся 60 дней. Очистка удаляет старые `scheduled_report_runs` и соответствующие `.xlsx` файлы. Если файл был удален вручную или недоступен, UI показывает запись истории без кнопки скачивания.

## SMTP Настройки

Вместо IMAP используется SMTP, потому что задача требует отправку писем, а не чтение входящей почты.

Настройки доступны только в админской зоне:

- host;
- port;
- secure mode: SSL/TLS или STARTTLS;
- username;
- password;
- from email;
- from name;
- тестовая отправка на указанный email.

Пароль после сохранения не возвращается в UI. Экран показывает только состояние "пароль задан" или "пароль не задан". При сохранении пустого пароля существующий пароль не перезаписывается, если администратор явно не выбирает сброс.

Секреты не коммитятся и не попадают в `.env.example` как реальные значения. Runtime-файл в `data/` должен быть доступен на запись пользователю контейнера `node`.

## Планировщик

Планировщик строится по образцу `preloadScheduler`:

1. при старте приложения читает включенные расписания;
2. ставит `setTimeout` до ближайшего запуска;
3. после завершения запуска пересчитывает следующий таймер;
4. при изменении расписания пересоздает таймеры;
5. предотвращает параллельный запуск одного и того же расписания.

Первая версия поддерживает ежедневную отправку в формате `HH:mm` и timezone `Europe/Moscow`. Поле `timezone` сохраняется в модели, чтобы позже расширить правила до недельных или месячных расписаний без смены схемы.

Ручной запуск из UI использует тот же runner, но `trigger = manual`. Тест SMTP использует `trigger = test` и не создает полноценный бизнес-отчет, если проверяется только почтовое подключение.

## Выполнение Отчета

Единый runner выполняет плановые и ручные запуски:

1. Проверяет, что отчет и расписание включены, если запуск плановый.
2. Создает `scheduled_report_runs` со статусом `running`.
3. Валидирует SQL и выполняет запрос в ClickHouse с лимитом строк и таймаутом.
4. Формирует `.xlsx` файл.
5. Сохраняет файл в `data/scheduled-report-files/`.
6. Отправляет письмо через SMTP с `.xlsx` во вложении.
7. Фиксирует `success` или `failed`, количество строк, размер файла, получателей и безопасное сообщение ошибки.

Если SQL или ClickHouse падают до формирования файла, run получает `failed` без `file_path`. Если файл создан, но SMTP не отправил письмо, run получает `failed`, а файл остается доступен в истории для диагностики и ручной передачи.

## Excel Формат

Все отправляемые отчеты формируются как `.xlsx`.

Правила генерации:

- первый лист содержит результат SQL-запроса;
- первая строка содержит имена колонок;
- строки результата сохраняются ниже;
- числа и даты сохраняются в безопасном представлении, пригодном для Excel;
- строки, начинающиеся с `=`, `+`, `-`, `@`, экранируются как текст, чтобы Excel не выполнял формулы из данных;
- применяется лимит строк и максимальный размер файла;
- имя файла строится из id отчета, даты запуска и id run.

В первой версии не требуется сложное форматирование, сводные таблицы или несколько листов. Это сохраняет генератор предсказуемым и тестируемым.

## UI

Добавляется раздел `Регулярные отчеты`.

Для пользователя с `scheduled-report-author`:

- список отчетов;
- создание и редактирование SQL-отчета;
- поле SQL;
- лимит строк;
- таймаут;
- включение или выключение отчета;
- проверка SQL с preview первых строк.

Для пользователя с `scheduled-report-delivery`:

- расписания выбранного отчета;
- время отправки;
- список получателей;
- тема и текст письма;
- включение или выключение расписания;
- история отправок;
- скачивание `.xlsx` за последние 60 дней;
- ручной запуск отправки.

Для администратора:

- отдельный экран SMTP-настроек в админской зоне;
- тестовая отправка.

UI остается плотным рабочим инструментом без маркетинговых блоков. Визуальный стиль следует существующим админским экранам `/admin/preload` и `/admin/users`.

## Аудит

Через существующий `userActivityStore` записываются события:

- создание отчета;
- изменение отчета;
- проверка SQL;
- создание или изменение расписания;
- ручной запуск;
- скачивание файла;
- изменение SMTP-настроек;
- тест SMTP.

Activity-log пишет тип действия, метод, путь, раздел и время. Тело SQL, получатели, SMTP username/password и email body в activity-store не сохраняются.

## Ошибки

Ошибки группируются для UI и истории:

- SQL не прошел валидацию;
- ClickHouse недоступен или вернул ошибку;
- превышен лимит строк;
- превышен лимит размера файла;
- не удалось сформировать `.xlsx`;
- SMTP не настроен;
- SMTP отказал в отправке;
- файл истории уже удален по retention или недоступен.

Пользователь видит короткое безопасное сообщение. Подробности с секретами не сохраняются и не рендерятся.

## Конфигурация

Добавляются переменные окружения с безопасными значениями по умолчанию:

```dotenv
SCHEDULED_REPORT_STORE_PATH=./data/scheduled-reports.sqlite
SCHEDULED_REPORT_FILE_DIR=./data/scheduled-report-files
SCHEDULED_REPORT_RETENTION_DAYS=60
SCHEDULED_REPORT_DEFAULT_ROW_LIMIT=10000
SCHEDULED_REPORT_MAX_ROW_LIMIT=100000
SCHEDULED_REPORT_MAX_FILE_SIZE_BYTES=10485760
SCHEDULED_REPORT_QUERY_TIMEOUT_MS=120000
```

SMTP-настройки хранятся в runtime-store и редактируются через админский UI. При необходимости позже можно добавить env-only режим для деплоев, где секреты должны приходить только из окружения.

## Тестирование

Автоматические тесты должны покрыть:

- нормализацию новых прав и запрет `mail-settings-admin` для аналитиков;
- доступ к маршрутам author, delivery и SMTP-admin;
- валидацию SQL и запрет mutation-запросов;
- применение лимитов строк, таймаута и размера файла;
- генерацию `.xlsx`;
- защиту от Excel formula injection;
- создание, обновление и чтение SQLite-store;
- планировщик и предотвращение параллельного запуска одного расписания;
- успешную SMTP-отправку через mock transport;
- ошибку SMTP без утечки секрета;
- retention 60 дней для истории и файлов;
- ручной запуск и скачивание файла;
- activity events для ключевых действий без тела SQL и SMTP-секретов.

Ручная проверка:

- создать SQL-отчет через UI;
- проверить preview;
- создать расписание с двумя получателями;
- выполнить ручную отправку;
- скачать файл из истории;
- убедиться, что аналитик без `scheduled-report-delivery` не видит получателей, историю и скачивание;
- убедиться, что аналитик не видит SMTP-настройки.

## Вне Скоупа Первой Версии

- IMAP и чтение входящей почты;
- произвольные недельные, месячные или cron-расписания;
- несколько листов Excel;
- визуальное форматирование Excel;
- прикрепление PDF;
- шифрование файлов отчетов на диске;
- персональные получатели по строкам результата;
- SQL-параметры с пользовательскими формами.
