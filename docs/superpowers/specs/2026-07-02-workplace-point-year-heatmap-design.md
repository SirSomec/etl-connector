# Дизайн: годовая дневная лента в карточке точки

## Цель

Добавить в карточку точки компактную дневную тепловую ленту по текущему году. Блок должен быть аналогичен дневной ленте из дашборда `Анализ точек`, но всегда загружаться за полный текущий год и помогать быстро увидеть сезонность, регулярность заказа и провалы по конкретной точке.

## Поведение

- Блок отображается в карточке точки над существующим подробным календарем заказа и SLA.
- Период блока фиксирован: с 1 января по 31 декабря текущего года относительно серверной даты.
- Пользовательский период `from/to` из карточки точки не влияет на годовую ленту.
- Остальные фильтры карточки точки сохраняются: `workplaceId`, профессии, тип заказа, статусы смен, `includeDeletedOrders`, `includeHiddenOrders`.
- Если данных нет, блок показывает спокойное пустое состояние без ломки секции графиков.
- Текущий день подсвечивается так же, как в существующих календарных визуализациях.

## Данные

Секция использует существующую дневную агрегацию карточки точки:

- `ordered_shifts`: дневная сумма `mg_orders.amount`;
- `completed_shifts`: успешные подтвержденные смены;
- `forecast_sla_active_shifts`: прогнозная активная часть SLA для текущих и будущих дней;
- `dropoffs_24h`, `avg_order_lead_minutes`, `min_order_lead_minutes` остаются доступными в строке, но в самой годовой ленте основной визуальный канал использует заказ и выполнение.

Для годового блока создается отдельный набор фильтров на базе текущих фильтров точки, где меняются только даты:

- `from = YYYY-01-01`;
- `to = YYYY-12-31`;
- `toExclusiveDateTime = (YYYY + 1)-01-01 00:00:00`;
- `rangeDays = 365` или `366`.

## Архитектура

Добавить новую прогрессивную секцию `year-heatmap` в `WORKPLACE_POINT_SECTION_NAMES`. Она загружается и кешируется отдельно от текущих секций `summary`, `charts`, `radius`.

Причина отдельной секции: годовой запрос может быть тяжелее текущего диапазона, поэтому он не должен задерживать подробный календарь, профессии или KPI. Кеш-ключ секции должен учитывать текущий год и все недатовые фильтры, но не пользовательские `from/to`.

В модели карточки точки добавить поле `yearHeatmapRows` или близкое по смыслу. Для full-load сценария `loadWorkplacePointDashboard` секция также должна загружаться, чтобы не было расхождения между прогрессивным и полным рендером.

## Рендер

Годовой блок размещается первым внутри `renderWorkplacePointCharts`, над `renderPointCalendar(...)`.

Визуально это не месячный календарь, а плотная дневная лента:

- все дни года выводятся в пределах доступной ширины контейнера;
- блок не вызывает горизонтальный скролл всей страницы;
- при узкой ширине лента переносит месячные группы на несколько строк или использует компактную сетку с `grid`/`flex-wrap`;
- начало месяца отмечается подписью месяца и/или тонким разделителем;
- tooltip дня показывает дату, заказано и выполнено.

Для доступности блок получает понятный `aria-label`, а значение дня остается доступным через `title`. Цветовая шкала использует уровни `0-4`, как в ленте `Анализа точек`.

## SQL-info

Новый визуальный вывод агрегированных данных получает отдельный `metricId`, например:

- `workplace-point.charts.year-heatmap`

Описание должно объяснять, что это дневная тепловая лента планового заказа выбранной точки за текущий год. SQL-info может использовать тот же SQL-шаблон дневного запроса карточки точки, потому что меняется только диапазон параметров.

## Тестирование

Автоматические тесты должны покрыть:

- нормализацию годового диапазона текущего года;
- то, что пользовательские `from/to` не попадают в годовой диапазон секции;
- кеш-ключ `year-heatmap`, который отличается от `charts` и не зависит от пользовательских дат;
- загрузку `year-heatmap` через секционный loader с операцией `workplace point year heatmap`;
- заполнение всех дней года, включая пустые дни;
- рендер блока над подробным календарем;
- наличие месячных меток или разделителей;
- отсутствие CSS-паттерна, который создает горизонтальный скролл страницы для годовой ленты.

## Ограничения

Этот дизайн не меняет существующий подробный календарь: он остается привязанным к выбранному пользователем периоду и сохраняет кликабельную детализацию дня.

Годовая лента не добавляет пользовательский произвольный SQL и не сохраняет новые runtime-файлы.
