# Инструкции для агентов

## Язык

Все ответы пользователю, промежуточные сообщения, документация для пользователя и обсуждение решений веди только на русском языке.

Исключения допустимы только для кода, имен файлов, команд, SQL, переменных окружения, логов, внешних названий API и точных технических идентификаторов.

## Контекст проекта

Этот репозиторий содержит первую итерацию сервиса аналитики для данных платформы `mygig.ru`.

Сервис подключается к ClickHouse базе `etl`, показывает доступные таблицы, структуру колонок и preview строк. Данные `etl` отражают доменную модель MyGig: клиенты, рабочие места, заказы, смены, исполнители, платежи, пользователи, специальности, история смен, а также мобильную аналитику AppMetrica.

Перед проектированием новых дашбордов обязательно прочитай:

- `docs/mygig-etl-data-context.md`
- `README.md`
- `docs/superpowers/specs/2026-06-01-etl-analytics-service-design.md`

## Работа с данными

- По умолчанию для аналитики используй таблицы `mg_*`: они более типизированы для ClickHouse.
- Таблицы `mygig_*` рассматривай как более сырой слой выгрузки: в них часто есть `_sdc_*` поля, даты/массивы могут быть строками.
- Не добавляй пользовательский произвольный SQL в UI без отдельного согласованного дизайна безопасности.
- Не сохраняй реальные пароли, токены и `.env` в репозиторий.
- Для связей между таблицами используй `_id` и objectId-поля как строки.

## UX первой итерации

Интерфейс должен оставаться рабочим инструментом для аналитика: плотный, спокойный, без маркетинговых блоков. Новые экраны должны помогать строить и проверять аналитические гипотезы по MyGig, а не демонстрировать декоративные элементы.
