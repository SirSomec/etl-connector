# Дизайн SQL-инспектора метрик

Дата: 2026-06-03.

## Цель

Добавить в ETL Analytics прозрачность расчета метрик: каждый KPI, график, карта и расчетная таблица должны иметь маленькую кнопку `i`, которая открывает модальное окно с кратким пользовательским описанием метрики и SQL-запросом, на котором основан расчет.

Функция нужна для аналитиков и технических пользователей, которые проверяют гипотезы, сверяют цифры и объясняют происхождение показателей без доступа к произвольному SQL в UI.

## Область первой версии

В первой версии нужно:

- добавить отдельное общее право `sql-inspector`;
- показывать кнопки `i` только пользователям с этим правом;
- выдать это право администраторам автоматически;
- сделать право доступным для управляемых учетных записей в `/admin/users`;
- добавить общий UI-компонент кнопки и модального окна;
- добавить форматированный SQL-блок с подсветкой ключевых слов;
- добавить краткое описание метрики простым языком;
- покрыть текущие дашборды и их расчетные блоки SQL-info metadata;
- зафиксировать правило в документации: все будущие метрики и графические выводы данных должны добавлять SQL-инспектор.

Не входит в первую версию:

- выполнение SQL из модального окна;
- произвольный SQL ввод пользователем;
- редактирование SQL через UI;
- аудит открытия модальных окон;
- отдельные права на SQL по каждому дашборду;
- выгрузка SQL в файл.

## Рекомендованный подход

Использовать единый реестр SQL-info metadata и общий permission `sql-inspector`.

Metadata хранится рядом с серверной моделью дашборда или в общем модуле, если блок переиспользуется несколькими страницами. Рендеринг кнопки, модального окна, форматирования SQL и проверки права находится в `src/render.js` как общий helper.

Такой подход сохраняет текущую архитектуру Express + server-rendered HTML, не добавляет frontend-сборку и дает один обязательный паттерн для будущих доработок.

## Права доступа

Добавляется permission:

- `id`: `sql-inspector`;
- label: `SQL метрик`;
- description: `Просмотр SQL-запросов и простых описаний расчетных метрик.`

Администратор получает право автоматически через текущую логику `role === 'admin'`. Аналитики получают право только если оно выбрано в форме учетной записи.

Если у пользователя нет `sql-inspector`, HTML кнопок `i` и SQL-модалок не рендерится. Это важно: скрытие должно происходить на сервере, а не только через CSS.

Право не расширяет доступ к разделам. Пользователь видит SQL-инспектор только внутри тех дашбордов, на которые у него уже есть обычное право просмотра.

## UI

Кнопка:

- маленькая серая кнопка с текстом `i`;
- располагается в правом верхнем углу расчетного блока;
- не меняет размер карточки, графика или таблицы;
- имеет доступное имя вида `Показать SQL метрики: Заказано смен`;
- не рендерится для пользователей без права.

Модальное окно:

- ширина: `min(900px, calc(100vw - 32px))`;
- максимальная высота: `calc(100vh - 48px)`;
- тело прокручивается, если описание или SQL не помещаются;
- закрывается по кнопке, клику на backdrop и клавише `Escape`;
- содержит заголовок метрики;
- содержит краткое описание для технически не подготовленного пользователя;
- содержит SQL-блок в `pre > code`;
- SQL-блок имеет горизонтальную прокрутку для длинных строк.

Визуальный стиль остается спокойным и плотным: без декоративных карточек внутри модального окна, без маркетинговых объяснений, без больших цветовых акцентов.

## Подсветка SQL

Подсветка делается серверным helper-ом после HTML-экранирования токенов или безопасным токенизатором, который не вставляет пользовательский HTML.

Минимальная подсветка:

- ключевые слова ClickHouse и SQL: `SELECT`, `WITH`, `FROM`, `WHERE`, `GROUP BY`, `ORDER BY`, `JOIN`, `LEFT JOIN`, `INNER JOIN`, `COUNT`, `countIf`, `uniqExact`, `sum`, `toDate`, `ifNull`;
- параметры ClickHouse вида `{from:DateTime}` отдельным стилем;
- строковые литералы отдельным стилем;
- комментарии отдельным стилем, если они появятся в шаблоне.

Если подсветчик не распознал токен, он выводит его как обычный escaped text.

## Модель metadata

Каждый расчетный блок получает объект:

```js
{
  id: 'sales-by-project.summary.ordered-shifts',
  title: 'Заказано смен',
  description: 'Показывает, сколько смен было запрошено клиентами за выбранный период с учетом текущих фильтров.',
  sql: 'SELECT ...'
}
```

Требования:

- `id` стабилен и уникален в приложении;
- `title` совпадает с названием метрики или панели в UI;
- `description` написан простым языком без SQL-жаргона;
- `sql` показывает запрос или шаблон запроса, который относится к блоку;
- если UI-метрика считается из нескольких запросов, описание явно говорит, что итог собирается из нескольких наборов данных;
- если запрос параметризован, SQL показывает ClickHouse-параметры, а не реальные значения пользователя.

Metadata не должна содержать секреты, пароли, токены, значения `.env` или реальные пользовательские вводы.

## Покрытие текущих блоков

SQL-инспектор добавляется ко всем текущим расчетным дашбордам:

- `Продажи по проектам`;
- `Анализ точек`;
- `Детализация точки`;
- `Анализ городов`;
- `Тепловая карта`;
- `Отмены гигерами`.

Кнопка должна быть у:

- KPI-карточек;
- панелей графиков и мини-графиков;
- карт;
- расчетных таблиц;
- календарей и heatmap-блоков, если они визуализируют агрегированные данные.

Не требуется добавлять кнопку к:

- навигации;
- фильтрам;
- формам входа;
- форме управления учетными записями;
- статическим пояснениям;
- таблице preview строк на главной странице, если она показывает сырые данные, а не расчетную метрику.

## Безопасность

Произвольный SQL в UI не добавляется. Модальное окно только показывает заранее подготовленный сервером SQL-шаблон.

SQL не должен содержать реальные значения фильтров, если они могут быть пользовательским вводом. Вместо этого используются параметры ClickHouse, например `{from:DateTime}`, `{client:Array(String)}`.

Все строки в HTML экранируются. Подсветка синтаксиса не должна обходить `escapeHtml`.

Пользователь без `sql-inspector` не должен получать SQL в HTML ответа. Это касается и основных страниц, и progressive section fragments.

Любой новый модуль, KPI, график, карта, календарь, heatmap или расчетная таблица, которые выводят агрегированные данные, должны добавлять SQL-info metadata и тесты на видимость по праву `sql-inspector`. Исключение допустимо только для статического UI и preview сырых строк таблицы.

## Тестирование

Автоматические тесты должны покрыть:

- `PERMISSION_DEFINITIONS` содержит `sql-inspector`;
- admin получает `sql-inspector` автоматически;
- analyst получает `sql-inspector` только при выбранном праве;
- форма `/admin/users` показывает чекбокс `SQL метрик`;
- пользователь без права не получает кнопку `i` и SQL в HTML;
- пользователь с правом получает кнопку `i` и модальное окно;
- progressive section fragment не содержит SQL без права;
- SQL и description экранируются;
- подсветка SQL не ломает HTML и выделяет базовые ключевые слова;
- модальное окно имеет доступные атрибуты и кнопку закрытия;
- текущие дашборды рендерят SQL-info для KPI, графиков, карт и расчетных таблиц.

Ручная проверка:

- `npm test`;
- зайти администратором и убедиться, что кнопки `i` видны на дашбордах;
- открыть модальное окно, проверить описание, форматирование SQL и прокрутку;
- создать аналитика без `SQL метрик` и убедиться, что SQL-кнопок нет;
- выдать аналитику `SQL метрик` и убедиться, что кнопки появились только в доступных ему разделах;
- проверить узкий экран: модальное окно не выходит за viewport.

## Риски

- `src/render.js` уже большой. Общие helper-ы должны быть компактными; если объем станет существенным, их нужно вынести в отдельный модуль без изменения публичного поведения.
- SQL в metadata может рассинхронизироваться с реальным запросом. Поэтому запросы лучше экспортировать из модулей дашбордов и переиспользовать в metadata там, где это возможно.
- Некоторые UI-блоки считаются из нескольких запросов. Для них нужно показывать либо основной SQL-шаблон, либо несколько SQL-блоков в одной модалке, не упрощая описание до неверной формулы.
- Большие SQL-запросы могут быть длинными. Модалка должна иметь вертикальную и горизонтальную прокрутку внутри тела, а не растягивать страницу.
