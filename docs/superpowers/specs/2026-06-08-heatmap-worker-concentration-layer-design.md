# Дизайн слоя концентрации исполнителей для тепловой карты

## Цель

Добавить в дашборд `/dashboards/heatmap` подключаемый слой `Концентрация исполнителей`, который показывает на Leaflet-карте актуальные зоны плотности активных исполнителей за последние 30 дней относительно текущей даты.

Слой должен выглядеть как погодная карта: плавные полупрозрачные пятна поверх тайлов карты, но под существующими маркерами точек заказа.

## Контекст

Текущая тепловая карта уже строит точки спроса по выбранному месяцу из `mg_orders` и рассчитывает баланс активной базы вокруг точек заказа. Активная база для баланса зависит от фильтров `activeBaseMode` и `activeBasePeriod`.

Новый слой концентрации решает другую задачу: показать актуальную географическую плотность исполнителей, которые входили в приложение за последние 30 дней от момента запроса. Он не зависит от выбранного месяца заказа и не меняет текущие метрики баланса.

## Поведение пользователя

- На странице появляется переключатель слоя `Концентрация исполнителей`.
- По умолчанию слой выключен, текущая карта остается прежней.
- При включении слой отображается поверх карты как цветные пятна концентрации.
- Существующие маркеры точек заказа остаются кликабельными и визуально читаемыми.
- В легенде карты появляется шкала концентрации от низкой к высокой плотности.

## Данные

Источник активности:

- `appmetrica_sessions.profile_id` как идентификатор пользователя сессии.
- `appmetrica_sessions.session_start_datetime` для окна активности.
- `mg_workers.user` для связи с пользователем.
- `mg_workers.location__coordinates` для геопозиции исполнителя.
- `mg_users` только для фильтрации удаленных пользователей.

Окно активности слоя всегда:

```sql
parseDateTimeBestEffortOrNull(s.session_start_datetime) >= now() - INTERVAL 30 DAY
AND parseDateTimeBestEffortOrNull(s.session_start_datetime) < now()
```

В браузер нельзя отдавать строки исполнителей или персональные поля. Сервер должен отдавать только агрегированные гео-ячейки:

- `lat`;
- `lon`;
- `activeUsers`;
- `intensity`.

## Агрегация

Сервер агрегирует активных исполнителей по координатной сетке. Первая версия использует округление координат до фиксированной точности, достаточной для регионально-городского анализа без вывода точных координат исполнителя.

Рекомендуемая форма запроса:

1. Выбрать уникальных активных пользователей из `appmetrica_sessions` за последние 30 дней от `now()`.
2. Связать их с `mg_workers`.
3. Оставить не удаленных исполнителей и пользователей с валидными координатами.
4. Если включен `activeBaseMode = ready`, применить тот же фильтр статусов `ready`, `booked`, `worked`, чтобы слой совпадал с выбранным пониманием активной базы.
5. Сгруппировать координаты по сетке и посчитать `uniqExact(user_id)`.
6. Рассчитать `intensity` на сервере относительно максимальной ячейки в текущей выдаче.

Фильтры заказа (`year`, `month`, `client`, `excludedProfession`, `addressSearch`) не должны ограничивать слой концентрации, потому что слой показывает актуальное предложение исполнителей, а не спрос выбранного периода.

## API и кеш

Секция `/dashboards/heatmap/section?section=map` остается единственным фрагментом карты. При включенном слое она загружает:

- существующие точки спроса;
- агрегированные ячейки концентрации.

В `normalizeHeatmapFilters` добавляется параметр:

- `workerConcentrationLayer`: `off` или `on`, по умолчанию `off`.

Ключ кеша секции должен включать `workerConcentrationLayer` и `activeBaseMode`, чтобы разные варианты слоя не смешивались. Окно слоя зависит от `now()`, но дневной кеш секций допустим: он соответствует существующей модели кеширования дашбордов до конца UTC-дня.

## Рендеринг

HTML карты получает два data-атрибута:

- `data-heatmap-points` для существующих точек заказа;
- `data-worker-concentration` для агрегированных ячеек концентрации.

Клиентский Leaflet-код:

1. Инициализирует обычную карту и тайлы.
2. Если `data-worker-concentration` не пустой, добавляет canvas-overlay слой.
3. Для каждой ячейки рисует несколько радиальных полупрозрачных заливок, чтобы получить мягкое пятно.
4. Затем рисует существующие `L.circleMarker` по точкам заказа.
5. При перемещении и масштабировании карты перерисовывает canvas.

Цветовая шкала слоя:

- низкая плотность: голубой;
- средняя: синий и желтый;
- высокая: оранжевый и красный.

## SQL-info

Так как слой является новым агрегированным визуальным выводом, нужно добавить отдельный `metricId` в `src/sqlMetricInfo.js`:

- `heatmap.map.worker-concentration`

Описание должно явно говорить, что слой считается по AppMetrica-сессиям за последние 30 дней от текущей даты и координатам `mg_workers.location__coordinates`, а не по выбранному месяцу заказа.

## Тестирование

Автоматические тесты:

- `normalizeHeatmapFilters` принимает только `workerConcentrationLayer = on|off` и по умолчанию ставит `off`.
- URL progressive-фрагмента сохраняет параметр слоя.
- `loadHeatmapDashboardSection` при выключенном слое не выполняет запрос концентрации.
- При включенном слое выполняется `heatmap worker concentration`.
- SQL концентрации использует `appmetrica_sessions`, `mg_workers`, `mg_users`, `now() - INTERVAL 30 DAY`, валидирует координаты и не использует таблицы `mygig_*`.
- Merge-модель возвращает `workerConcentration` без сырых пользовательских полей.
- Рендер карты выводит `data-worker-concentration`, переключатель слоя и легенду.
- SQL-info содержит `heatmap.map.worker-concentration` и не наследует родительский SQL.

Ручная проверка:

- открыть `/dashboards/heatmap`;
- убедиться, что карта без включенного слоя выглядит как раньше;
- включить слой и проверить, что пятна рисуются над тайлами и под точками заказа;
- проверить кликабельность маркеров точек;
- проверить консоль браузера на ошибки.

## Ограничения

- Слой не выводит персональные данные и точные строки исполнителей.
- Слой не заменяет текущую метрику `weightedActiveUsers`; это дополнительная визуальная подсказка.
- В первой версии не добавляется произвольная настройка радиуса, цвета или размера гео-ячейки.
- Фильтры клиента, профессии и адреса не применяются к концентрации исполнителей.
