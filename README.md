# ETL Analytics Service

Read-only web-сервис для просмотра ETL-данных в ClickHouse.

## Назначение

Сервис показывает доступные данные из ClickHouse базы `etl`, подключенной к данным платформы `mygig.ru`.

Первая итерация умеет:

- показывать список таблиц в настроенной ClickHouse базе;
- показывать колонки и ClickHouse-типы выбранной таблицы;
- показывать первые 100 строк выбранной таблицы;
- показывать первый дашборд `Продажи по проектам` по брендам MyGig на базе таблиц `mg_*`;
- показывать дашборд `Анализ точек` для оценки стабильности планового заказа по рабочим местам MyGig;
- показывать дашборд `Анализ городов` для оценки заказа и базы исполнителей по выбранному населенному пункту;
- показывать дашборд `Тепловая карта` с интерактивной картой заказов, улицами и радиальным балансом активной базы;
- запускаться в Docker с установленными Yandex Cloud CA сертификатами;
- читать параметры подключения из переменных окружения.

## Язык взаимодействия

Все дальнейшие ответы пользователю, обсуждение решений и пользовательская документация по этому проекту должны быть на русском языке. Исключения: код, команды, SQL, переменные окружения, имена файлов, логи и точные технические идентификаторы.

## Контекст данных

Доменный и ETL-контекст для будущих дашбордов описан в `docs/mygig-etl-data-context.md`.

Инструкции для будущих агентов находятся в `AGENTS.md`.

## Дашборды

Доступные экраны:

- `http://localhost:3000/` - список таблиц и просмотр структуры данных;
- `http://localhost:3000/dashboards/sales-by-project` - дашборд `Продажи по проектам`;
- `http://localhost:3000/dashboards/workplace-analysis` - дашборд `Анализ точек`;
- `http://localhost:3000/dashboards/city-analysis` - дашборд `Анализ городов`;
- `http://localhost:3000/dashboards/heatmap` - дашборд `Тепловая карта`;
- `http://localhost:3000/dashboards/worker-cancellations` - дашборд `Отмены гигерами` для анализа отмен и провалов смен по исполнителям;
- `http://localhost:3000/admin/activity` - администраторский мониторинг активности пользователей самого аналитического сервиса.

В дашбордах по умолчанию используются таблицы `mg_*`. Для `Продажи по проектам` проектом считается бренд клиента из `mg_clients.title`. В `Анализе точек` стабильность считается как доля дней с плановым заказом по `mg_orders.amount`. В `Анализе городов` город выбирается как город точки заказа, а база исполнителей считается по последней локации пользователя в радиусе 15 км от точек с выбранным спросом за период и фильтры. В `Тепловой карте` заказ берется за выбранный месяц и агрегируется по рабочим местам с координатами; точки без заказа в выбранном месяце не отображаются. Активная база по умолчанию берется за 30 дней до конца выбранного месяца, а переключатель периода входов позволяет ограничить ее исполнителями, которые входили в приложение в выбранном месяце; вклад исполнителя в точку заказа зависит от расстояния: до 5 км - полный, 5-10 км - половинный, 10-15 км - четверть, дальше 15 км - не учитывается. Карта строится на Leaflet и OpenStreetMap tiles.

## Конфигурация

Создайте локальный `.env` из `.env.example`:

```dotenv
CLICKHOUSE_HOST=rc1a-1kv5jd0taf1ef4ah.mdb.yandexcloud.net
CLICKHOUSE_PORT=8443
CLICKHOUSE_DATABASE=etl
CLICKHOUSE_USER=rouser
CLICKHOUSE_PASSWORD=change-me
CLICKHOUSE_CA_PATH=/usr/local/share/ca-certificates/Yandex/RootCA.crt
CLICKHOUSE_REQUEST_TIMEOUT_MS=120000
DASHBOARD_SECTION_CACHE_PATH=./data/dashboard-section-cache.json
WORKPLACE_DIRECTORY_CACHE_PATH=./data/workplace-directory-cache.json
PRELOAD_STORE_PATH=./data/preload.sqlite
USER_ACTIVITY_STORE_PATH=./data/user-activity.sqlite
AUTH_ENABLED=true
AUTH_ADMIN_EMAIL=admin@example.com
AUTH_ADMIN_PASSWORD=change-me
AUTH_USER_STORE_PATH=./data/users.json
AUTH_SESSION_SECRET=change-me-session-secret
AUTH_SESSION_COOKIE_NAME=etl_analytics_session
AUTH_SESSION_TTL_MS=43200000
PORT=3000
```

Реальный пароль задавайте только в локальном `.env` или в окружении деплоя. Не коммитьте `.env`.

Новые секции дашбордов кешируются до конца текущего UTC-дня; просроченные записи автоматически удаляются при чтении, записи и ежедневной фоновой очистке на границе UTC-дня. По умолчанию кеш хранится в `./data/dashboard-section-cache.json`; путь можно переопределить через `DASHBOARD_SECTION_CACHE_PATH`. Справочник точек для подсказок в дашборде `Анализ точек` хранится в `./data/workplace-directory-cache.json` и обновляется фоново не чаще одного раза в 7 дней; путь можно переопределить через `WORKPLACE_DIRECTORY_CACHE_PATH`.

### Предзагрузка витрин

Первая итерация предзагрузки использует локальную SQLite-базу `data/preload.sqlite`; путь можно переопределить через `PRELOAD_STORE_PATH`. Это runtime-файл в `./data`, его не нужно коммитить вместе с кодом.

Страница управления `/admin/preload` требует права `Предзагрузка витрин` / permission `preload-admin`. Пилотная витрина ускоряет дашборд `Продажи по проектам`: расписание по умолчанию запускается ежедневно в `03:00 Europe/Moscow` и пересчитывает последние 45 дней. Ручной запуск позволяет выбрать диапазон дат.

В Docker volume `./data:/app/data` должен быть доступен на запись пользователю контейнера `node` (`uid 1000`), иначе обновления SQLite/store будут падать с `EACCES`. Если витрина отсутствует, не покрывает выбранный период или недоступна, дашборд сохраняет текущее поведение и читает данные напрямую из ClickHouse fallback.

Авторизация включена по умолчанию. Администратор по умолчанию берется из `AUTH_ADMIN_EMAIL` и `AUTH_ADMIN_PASSWORD`, отображается в UI как read-only запись и не сохраняется в `data/users.json`. Управляемые учетные записи создаются через `/admin/users`, пароли хранятся только в виде PBKDF2-хешей. Для локального отключения авторизации можно задать `AUTH_ENABLED=false`.

Управляемые пользователи могут самостоятельно сменить пароль на `/account/password`. Пароль, заданный администратором при создании учетной записи или сбросе пароля, считается временным: при следующем входе пользователь обязан задать собственный пароль перед доступом к таблицам, дашбордам и админским действиям. Существующие записи в `data/users.json`, у которых еще нет отметки о самостоятельной смене, также потребуют смену при следующем входе. Env-администратор меняет пароль только через `AUTH_ADMIN_PASSWORD`.

Минимальные требования к паролю managed-пользователя: не менее 12 символов, строчная и заглавная буквы, цифра, спецсимвол, без пробелов. Пароль не должен совпадать с текущим паролем, email, локальной частью email или очевидными слабыми значениями вроде `password`, `qwerty`, `123456`, `change-me`, `admin`, `analyst`.

Мониторинг активности пользователей сервиса хранится в SQLite-файле `./data/user-activity.sqlite`; путь можно переопределить через `USER_ACTIVITY_STORE_PATH`. Экран `/admin/activity` доступен только администраторам и показывает активность пользователей самого аналитического сервиса, а не пользователей MyGig из `mg_users`. В события пишутся только тип действия, метод, путь без query string, раздел и время; body, headers, параметры фильтров и секреты не сохраняются.

Право `SQL метрик` включает серые кнопки `i` на расчетных KPI, графиках, картах и таблицах дашбордов. Кнопка открывает краткое описание метрики и SQL-шаблон расчета. Для каждого отображаемого значения используется явный `metricId` с собственным SQL-info; автоматическая подстановка родительского запроса вместо точного запроса метрики запрещена. Без этого права SQL не попадает в HTML страницы или progressive-фрагмента.

Файлы в `./data` используются для кешей, SQLite-хранилищ и управляемых учетных записей. В Docker volume `./data:/app/data` должен быть доступен на запись пользователю контейнера `node` (`uid 1000` в официальном Node-образе). При деплое создайте директорию заранее и проверьте права, иначе запись кеша, пользователей, предзагрузки или `user-activity.sqlite` будет падать с `EACCES`.

## Локальная разработка

Установить зависимости:

```bash
npm install
```

Запустить тесты:

```bash
npm test
```

Запустить приложение локально:

```bash
npm start
```

Локальный `npm start` читает конфигурацию из переменных окружения процесса, а не из `.env` автоматически. Перед запуском экспортируйте переменные из `.env` или задайте их в shell.

Также для локального запуска нужны Yandex Cloud CA сертификаты на хосте или `CLICKHOUSE_CA_PATH`, указывающий на читаемый CA сертификат.

После запуска откройте `http://localhost:3000`.

Для дашбордов с месячными периодами запросы к ClickHouse могут занимать десятки секунд,
поэтому рекомендуемый `CLICKHOUSE_REQUEST_TIMEOUT_MS` — `120000`.

## Docker

Собрать образ:

```bash
docker build -t etl-analytics-service .
```

Запустить через compose:

```bash
docker compose up --build
```

Compose читает конфигурацию из локального `.env`, поэтому создайте файл перед запуском.

После запуска откройте `http://localhost:3000`.

Для удаленного сервера перед запуском подготовьте writable volume:

```bash
mkdir -p data
sudo chown -R 1000:1000 data
```

Файловые кеши пишутся атомарно через уникальные временные файлы в той же директории. Если добавляете новый файловый кеш или JSON-хранилище, учитывайте холодный старт и параллельные запросы: нельзя использовать общий путь вида `cache.json.tmp` для всех записей.

## Безопасность

- Web UI не принимает произвольный SQL.
- Используйте read-only пользователя ClickHouse.
- Настроенный пароль маскируется в ошибках, которые показываются в браузере.
- Пароли учетных записей сервиса хранятся только в виде хешей; env-пароль администратора задается только через окружение.
- Пароли managed-пользователей создаются и сбрасываются администратором как временные; пользователь обязан сменить такой пароль самостоятельно на `/account/password`.
- `.env` игнорируется git.
- В данных MyGig есть персональные данные. Не выводите PII в дашборды без явной необходимости и маскирования.
- Дашборд `Отмены гигерами` намеренно выводит ФИО и полный телефон исполнителя для операционной работы с отменами; остальные персональные поля не выводятся.
